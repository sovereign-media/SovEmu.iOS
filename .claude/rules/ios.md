# SovEmu.iOS

Two SwiftUI apps: `SovEmu` for iPhone and iPad (iOS 18), and `SovEmuTV` for Apple TV (tvOS 18,
after SovEmu.Android's TV app at 1 dp = 1.5 points). How Swift is
written is [ios-swift.md](ios-swift.md); tests are [ios-tests.md](ios-tests.md). Paths into SovEmu
below are from the parent repository's root.

## Layout

- **Change the project in `project.yml`**, never in Xcode's project editor; `SovEmu.xcodeproj` is
  generated by XcodeGen and gitignored.
- **`Packages/SovEmuKit` holds the logic, UI-free**: the wire protocol, API models and client,
  sign-in, controllers, game lists, latency and stream statistics, with Swift Testing tests
  (`swift test` on the host). It imports Foundation, Synchronization, Security, CryptoKit (PKCE) and Apollo only, and
  builds in Swift 6 language mode (tools 6.0).
- **The apps only draw and do I/O**: SwiftUI views, GameController, WebRTC, AVFoundation.
  `Apps/Shared` is in both targets (the player, the stream, controllers, the shared screens and
  `Platform.swift`'s adapters, where an iOS and a tvOS difference lives); `Apps/Mobile` is the
  iPhone and iPad app's own, `Apps/TV` the Apple TV's (its dock, Home, system page, search,
  sign-in and accounts, in-game menu). On tvOS the player owns the controllers and the remote
  while a game is on screen (`GameControllers`, GameController's event view controller): every
  press reaches it through GameController only, never as tvOS's Back or focus moves.
  Both build in Swift 5 mode only because it wraps WebRTC's Objective-C delegates. Logic that a
  test could check moves down into SovEmuKit.
- **WebRTC is a binary package**, `Packages/WebRTC`: LiveKit's build of libwebrtc (it has tvOS
  slices), fetched by `scripts/fetch-webrtc.sh` (pinned by SHA-256, gitignored). LiveKit prefixes
  every type with `LK`; the package's `WebRTC` module re-exports them under WebRTC's own names
  (`Names.swift`), so code writes `RTCPeerConnection`. A type the apps start to use gets its
  alias there. To move the build, change `VERSION` and `SHA256` together; never commit the
  framework.

## Shared with the other clients

- **SovEmuKit is a port**: its files name their SovEmu.Web and SovEmu.Android counterparts in the
  header, and keep their names and test cases. Change a behaviour in all three clients together.
- **The wire protocol** (`SovEmuKit/Protocol.swift`, `WireProtocol`) mirrors
  `SovEmu.Backend/SovEmu.Protocol/src/input.rs`, `SovEmu.Web/src/lib/protocol.ts` and
  SovEmu.Android's `Protocol.kt` byte for byte; `ProtocolTests` uses the same vectors.
- **Controllers follow SovEmu's `docs/CONTROLLERS.md`** (IDs, families, positional input names,
  keyboard `KeyboardEvent.code` names, default mappings, hotkeys, players), in
  `SovEmuKit/Controllers.swift`; the app only reads GameController into it. Defaults map by
  position (GameController's `buttonA`, the bottom face, is `south` = RetroPad B).
- **Signalling** is one `sessionOffer` mutation with the complete offer (non-trickle: wait for ICE
  gathering, at most 1.5 s, then send what there is), as on the other clients.

## GraphQL and sign-in

- **GraphQL goes through Apollo iOS** (pinned exactly in `Package.swift`). Every operation is
  written once in `SovEmuKit/GraphQL/operations.graphql` (names as in SovEmu.Android's
  `operations.graphql`) and generated by `scripts/codegen.sh` into `SovEmuKit/Generated/`
  (committed, `internal`; never edit it, except the custom scalars under
  `Generated/Schema/CustomScalars/`, which codegen leaves alone). Codegen checks every document
  against `GraphQL/schema.graphqls`, a copy of `SovEmu.Backend/SovEmu.Server/schema.graphql`:
  refresh it with `scripts/sync-schema.sh` when the server's schema changes. CI fails when
  `Generated/` is out of date.
- **Generated types stop at `GraphQLMapping.swift`**: the app sees only the public models in
  `API.swift` and `Library.swift`. An enum value a newer server adds maps to the model's fallback
  there. A new operation is a document, codegen, a mapper, a `SovEmuAPI` method and an `APITests`
  case against the stub server (which adds each object's `__typename`, as the server does,
  `Typenames.swift`).
- **One client per server, no cache**: `BearerInterceptor` adds the access token and spends one
  refresh-and-retry on `UNAUTHENTICATED` (or a 401); every failure reaches callers as `APIError`.
  GraphQL `Int` arguments are `Int32` (`int32(_:)`).
- **Every sign-in URL and the client id come from `bootstrapConfig`** (`deviceClientId`: the app
  signs in as the device client); only `/graphql` is fixed. As Sovereign's phones, *Sign in*
  opens the server's own page in the system browser (`webAuthenticationSession`, not ephemeral;
  `BrowserSignIn.swift`: the code flow with PKCE as the **mobile client**, the redirect's `state`
  checked first); a stored sign-in remembers its client (`RefreshTokenStore.loadClientId`) for
  refresh and sign-out. *Sign in a TV* (the account) approves a TV's code with
  `approveDeviceCode`. As on Sovereign's TVs and SovEmu.Android, too:
  *Sign in with your phone* (the device grant, `DevicePairing.swift`'s `awaitApproval`, the view
  `PairingView` with Core Image's QR code), with the password as the fallback, and only the code
  when the server has the password off. `TokenClient` (an actor) refreshes one at a time and rotates the
  refresh token, kept in the Keychain this-device-only; the access token stays in memory.
- **Several accounts and servers are SovEmuKit logic**, ported from SovEmu.Android's
  `Accounts`/`AccountStore`/`Connection`/`Launch` (same names, cases and v1 stored format):
  `AccountStore` (the list, active id and device names in a `KeyValue`, each refresh token in an
  `AccountTokenStore`, the Keychain this-device-only), *Who's watching?* and *Choose a server*
  (`KnownServers`, `ServerChooser` over the app's `ServerService` and `AccountSession`), and the
  proxy headers (`CustomHeaderRules`; `CustomHeaderInterceptor` puts them on every request to the
  server's host and port, through `SovEmuAPI`'s and `TokenClient`'s `customHeaders`, never logged).
  The Apple TV app uses them through `Apps/TV/TVSession.swift`, which drives `AppModel` (the
  active account's client) for the shared screens; the iPhone app keeps its one sign-in.

## Before a PR

What CI runs: `scripts/codegen.sh --check`, `swift test` in `Packages/SovEmuKit`,
`scripts/fetch-webrtc.sh`, `xcodegen generate`,
then `xcodebuild -project SovEmu.xcodeproj -scheme SovEmu -destination 'generic/platform=iOS
Simulator' CODE_SIGNING_ALLOWED=NO build`, and the same for `-scheme SovEmuTV` with
`'generic/platform=tvOS Simulator'`. Check what a user sees on the simulator; controllers and
the Siri Remote on a real Apple TV (a debug build traces input on its console, `inputTrace`).
